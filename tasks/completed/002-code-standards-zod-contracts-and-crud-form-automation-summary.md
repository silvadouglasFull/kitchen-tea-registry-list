### 2. shadcn-zod-form configuration

- Initialized via `npx shadcn-zod-form@latest init`, which added `"form": "@/components/form"` to `components.json`.
- The generate command is usable as:
  ```bash

- Output: physical `.tsx` file using React Hook Form + `zodResolver` + shadcn/ui components + Tailwind CSS. No `AutoForm`, no runtime generation.

### 3. Plop.js — `plopfile.js` and templates

`plopfile.js` at the project root registers a single `module` generator via `npx plop module`. It:

1. Prompts for a module name, validates it is non-empty kebab-case.
2. Normalizes the input (trims, lowercases, replaces non-alphanumeric with `-`).
3. Uses `skipIfExists: true` on every action to prevent accidental overwrites.
4. Generates 8 files across 4 layers with correct naming conventions.

Templates in `plop-templates/module/`:

| Template | Generates |
| :--- | :--- |
| `domain/schemas/module.schema.ts.hbs` | `<module>.schema.ts` — domain/output schema |
| `application/schemas/create-module.schema.ts.hbs` | `create-<module>.schema.ts` — creation input schema |
| `application/schemas/update-module.schema.ts.hbs` | `update-<module>.schema.ts` — update input schema |
| `application/services/module-service.ts.hbs` | `<module>-service.ts` — business-rules service |
| `application/actions/create-module-action.ts.hbs` | `create-<module>-action.ts` — `'use server'` create action |
| `application/actions/update-module-action.ts.hbs` | `update-<module>-action.ts` — `'use server'` update action |
| `infrastructure/repositories/module-repository.ts.hbs` | `<module>-repository.ts` — Drizzle ORM repository |

The `presentation/components/` directory is created with a `.gitkeep`; forms are added separately via `shadcn-zod-form`.

### 4. Zod schema conventions enforced in every template

- Filenames: `kebab-case`.
- Schema constants: `camelCase` (e.g. `createRegistrySchema`).
- Inferred TypeScript types: `PascalCase` via `z.infer<typeof schema>` (e.g. `CreateRegistryInput`, `Registry`).
- Domain schema extends the creation schema via `.extend({ id, createdAt })`.
- Persistence-managed fields (`id`, `createdAt`, `updatedAt`, `deletedAt`) excluded from creation and update input schemas.
- No `drizzle-zod` imports anywhere.
- Server Actions call `schema.safeParse(rawInput)` before invoking the service and return `{ success, error?, data? }`. Internal errors are never exposed to the caller.

The `create-registry-form.tsx` was generated with:

```

The generated import path was corrected from an absolute traversal to the correct relative path within the module.

### 6. ESLint fix — `plopfile.js`

The anonymous `export default function(plop){}` triggered an `import/no-anonymous-default-export` warning. Fixed by naming the export: `export default function plopConfig(plop){}`.

### 7. Database client stub

Added `src/shared/database/client.ts` — a typed `any` stub exporting `db` so generated repositories resolve the `@/shared/database/client` import and TypeScript compiles cleanly. This file is replaced with the real Drizzle + pg client in Task 003.
